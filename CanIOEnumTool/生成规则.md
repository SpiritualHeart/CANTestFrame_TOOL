# Debug_Excel 功能需求

> 用于AI软件生成C代码，导入Excel解析CAN信号，自动生成CAN测试帧函数

## 一、功能概述
用户导入Excel文件，程序解析Excel内CAN信号定义，**从第2个工作表(Sheet)开始**，忽略第1个工作表，为每一个工作表自动生成对应的C语言CAN测试帧函数。

## 二、输入要求
- 文件格式：`.xlsx` / `.xls`
- 文件包含多个工作表Sheet，跳过第1个Sheet，处理剩余全部Sheet

## 三、工作表Sheet解析规则
每个Sheet对应生成1个独立测试帧函数。

### 3.1 函数命名规则
```c
app_can_test_frame_<Sheet名称>
```

> 固定前缀 `app_can_test_frame_` + 当前工作表 Sheet 名称
> Sheet 名称包含空格、`-`、特殊符号时，全部替换为下划线`_`，保证 C 函数名合法。

### 3.2 行号规则

| 行号 | 说明 |
| --- | --- |
| 第 11 行 | 参数名称表头行，仅做参考，不参与代码生成 |
| 12 行及以后 | 真实业务数据行，逐行解析处理 |

### 3.3 列映射定义

| Excel 列 | 字段名称 | 业务含义 |
| --- | --- | --- |
| A 列 | Byte 字节 | 取值范围 0~7，代表 CAN 帧内字节序号；同一个 A 列数值属于同一个字节分组 |
| B 列 | Bit 位 | 信号占用 bit 起始位置；可以为空，为空时当C列数据不为空表示占据1个字节，如果C列数据为空表示该字节无数据 |
| C 列 | Signal 数据 | 信号 / 变量名称，代表 bit 含义，支持单元格合并，合并单元格数量代表信号占用 bit 位数，可以为空，为空表示没有数据 |
| D 列 | Type 类型说明 | 可选参考列，仅作人工阅读备注，不参与解析与代码生成（位宽完全由 C 列合并格数决定） |
| E 列 | TestFrameID | 用户配置的 CAN 测试帧 ID |

### 3.4 A 列（Byte 列）单元格形态规则

A 列不为空时只会出现以下两种形态，其他形态均视为格式错误：

| A 列单元格形态 | 含义 |
| --- | --- |
| 单个单元格（无合并） | 该行数据占用完整 1 个字节（8bit）；此时 B 列必须为空，C 列为空表示该字节无数据 |
| 8 个单元格纵向合并 | 该 1 个字节上包含多位数据，合并范围内 8 行逐行定义 bit（B 列为 bit 编号 0~7） |

补充约束：

1. 当前行 A 列为空（且不在合并范围内）时，表示数据结束；其后所有行的 A 列必须均为空，若其后仍出现 Byte 数据（含新的合并）则视为格式错误；
2. Byte 数值以 0~7 一组一组完整出现（每组对应一个 CAN 测试帧）：每组从 0 开始、连续递增且必须到 7 结束；一组未到 7 即停止（如一组止于 6、缺少 byte 7）或组内跳号/重复，均视为格式错误；
3. A 列为空表示数据结束的行，其 B / C 列不应再有数据，否则视为格式错误（通常是漏填 Byte 列）；
4. A 列合并只允许纵向单列合并（仅 A 列自身、8 行），不得横向跨列合并、不得与其他列合并；表头行及以上区域的装饰性合并不参与校验。

### 3.5 B 列（Bit 列）规则

| 场景 | 规则 |
| --- | --- |
| A 列为单个单元格 | B 列必须为空（该行占用完整 1 字节），非空即格式错误 |
| A 列为 8 格合并 | 组内 8 行 B 列必须依次填写 0、1、2、3、4、5、6、7：整数、完整、不跳号、不重复；任何一行缺失、非整数或顺序错乱均视为格式错误 |

补充约束：

1. B 列不得使用合并单元格（数据区内）；
2. B 列值只能为 0~7 的整数。

### 3.6 C 列（Signal 列）规则

按 A 列形态分两种场景：

| A 列形态 | C 列形态 | 含义 |
| --- | --- | --- |
| 单个单元格 | C 单格（无合并） | 整字节信号，生成代码时直接赋值 |
| 单个单元格 | C 为空 | 该字节无数据（padding 字节，填 0x00） |
| 单个单元格 | C 纵向 n 格合并 | 跨 n 字节的多字节信号（如 4 格合并 = 32bit 变量占 4 个字节）；合并范围内各行的 A 列 Byte 值必须连续递增（如 0,1,2,3） |
| 8 格合并 | C 单格 | 1bit 信号 |
| 8 格合并 | C 纵向 n 格合并 | n bit 信号（如 2 格合并 = 2bit），信号占用合并范围内 B 列对应的连续 bit |
| 8 格合并 | C 为空 | 该 bit 无数据（padding bit，填 0） |

示例——u32 变量 `res_value` 占 4 字节、u16 变量 `res_value_ADDES` 占 2 字节（**合法，此即多字节信号的标准表达方式**）：

| Byte | bit | Debug Msg define |
| --- | --- | --- |
| 0 |  | res_value（C12:C15 合并） |
| 1 |  | （合并范围） |
| 2 |  | （合并范围） |
| 3 |  | （合并范围） |
| 4 |  | res_value_ADDES（C16:C17 合并） |
| 5 |  | （合并范围） |
| 6 |  | （无数据，padding） |
| 7 |  | （无数据，padding） |

补充约束：

1. C 列合并只允许纵向单列合并（仅 C 列自身），不得横向跨列合并；
2. C 列合并能否跨字节取决于 A 列形态，两种场景规则相反：
   - **A 单格行上的 C 合并（多字节信号）**：允许且必须跨字节——C 合并跨越的 n 行就是信号的 n 个字节，这是 u32/u16 等跨字节变量的唯一合法表达方式；
   - **8 格合并组内的 C 合并（多 bit 信号）**：不得跨字节——C 合并代表同一字节内的连续 bit，只能在所在 byte 组的 8 行范围内，不得延伸出组边界；
3. A 单格行上的 C 合并，其合并行数即信号字节数，且合并范围内各行的 A 列必须均为单格且 Byte 连续递增（如 4 格合并对应 Byte 0,1,2,3）；
4. 信号名必须是合法的 C 表达式：以字母或下划线开头，可包含数组下标 `[n]`、结构体/联合体成员访问 `.` 或 `->`、函数调用 `()`；不得包含中文或其他非法字符；
5. 同一 byte 组内信号 bit 区间不得重叠（重叠时后解析行覆盖前面数据，输出告警）。

## 四、信号位宽判定逻辑

**信号位宽完全由 C 列合并单元格数量决定**，与信号是函数还是变量、BOOL 还是非 BOOL 均无关：

| 场景（A 列形态） | C 列形态 | 信号位宽结果 |
| --- | --- | --- |
| 8 格合并组内 | C 单格（无合并） | 1bit |
| 8 格合并组内 | C 纵向 n 格合并 | 位宽 = n（n bit 信号，如 2 格合并 = 2bit） |
| 单个单元格 | C 单格（无合并） | 8bit（整字节信号） |
| 单个单元格 | C 纵向 n 格合并 | 位宽 = n×8（跨 n 字节的多字节信号，如 4 格合并 = 32bit） |

> 注意：C 列合并单元格的行数直接等于信号占用 bit 数目（A 单格行场景下等于字节数 ×8）。

## 五、C 代码生成逻辑

**按 A 列 Byte 字节分组处理，同一字节下所有信号归为一组，根据组内信号位宽组合选择处理逻辑（与信号类型无关）**

### 5.1 单字节内信号位宽组合处理表

| 字节内部位宽场景 | 代码处理逻辑 | 参考模板函数名 |
| --- | --- | --- |
| 仅 1 个信号，且位宽 = 8bit（独占整字节） | 直接赋值，无需移位、或运算 | `app_can_test_frame_03_DiagADValue` |
| 组内信号全部为 1bit | 先初始化字节，再用 `BITn` 宏按位或；每个信号用 `if (x > 0u)` 条件判断置位 | `app_can_test_frame_09_sleepermit` |
| 组内存在 2~7bit 信号（或 1bit 与多位混合） | 字节先清零 `= 0u`，再对每个信号移位后按位或：1bit 信号用 `if (x > 0u)` 条件置 BITn；2~7bit 信号用 `(UINT8)x << n` 移位后 `|=` | `app_can_test_frame_02_tx_MMICFG` |

### 5.2 跨多字节信号处理

当单个信号位宽 > 8bit（如 16bit、32bit），按大端序对每一个涉及的字节分别执行移位操作：

```c
g_u8_tx_can_data[0] = (UINT8)(res_value >> 24u);   /* 32bit 信号的最高字节 */
g_u8_tx_can_data[1] = (UINT8)(res_value >> 16u);
g_u8_tx_can_data[2] = (UINT8)(res_value >> 8u);
g_u8_tx_can_data[3] = (UINT8)(res_value);          /* 最低字节 */
```

> 参考模板函数：`app_can_test_frame_04_reset`

### 5.3 函数通用结构约束

1. 每个生成函数输出 8 字节 CAN 帧数据；
2. 帧字节顺序严格 Byte0 ~ Byte7；
3. F 列的值作为该测试帧 CAN ID（详见 6.1 CAN ID 提取规则）；
4. Excel 没有定义的字节，默认填充`0x00`。

## 六、输出产物

1. 从第 2 个 Sheet 开始，每个 Sheet 生成一个 C 函数，命名遵守命名规则；
2. 全部函数输出完整可编译 C 源码 `.c`；
3. 每个 Sheet（第 2 个起）独立生成一份上位机 ini 配置文件和一份 DBC 文件，命名 `<Sheet名称>.ini` / `<Sheet名称>.dbc`（Sheet 名称中的非法文件字符替换为 `_`），保存到与 `.c` 相同目录。

### 6.1 CAN ID 提取规则

- ID 取自 Excel **F 列**（表头 `ID`）；个别表（如 0C）ID 位于其他列时，按内容特征（16 进制值）回退检测；
- 支持的原始写法：`7E0`、`0x7E0`、`ID7E0`（大小写均可），统一提取为大写十六进制（如 `7E0`）；
- 同一 Sheet 内出现多个 ID 时，按首次出现顺序分帧：**每个 CAN ID 对应一个 8 字节测试帧（一条 Message）**，该 ID 行范围内的信号归入对应帧。

### 6.2 ini 文件生成规则（参考 IO_Enum 模块 ini）

| 项目 | 规则 |
| --- | --- |
| 文件编码 | UTF-8 无 BOM，Windows CRLF 换行 |
| `$Message` | `Id（16 进制大写，无 0x）, 8, RX_<ID>, 10`（长度 8、Cycle=10） |
| `&Format` | `Motorola` |
| `@Signal` | `Start, Length, Name, 0`；Start = Byte×8 + bit 起始位（顺序编号），Length = 信号位宽 |
| 信号名 | C 列数据，非法字符替换为 `_`，帧内重名自动加 `_1`/`_2` 后缀 |
| `#Value` | 仅 1bit 信号附带 `0,OFF;` / `1,ON;` |
| 帧间分隔 | 每个 Message 块后空一行 |

### 6.3 DBC 文件生成规则（参考 IO_Enum 模块 DBC）

| 项目 | 规则 |
| --- | --- |
| 节点 | `BU_: BCM`，所有消息发送方为 BCM，接收方 `Vector__XXX` |
| `BO_` | `BO_ <十进制ID> RX_<16进制ID>: 8 BCM`（消息名统一 `RX_` 前缀，如 `RX_7E0`） |
| `SG_` | `SG_ <信号名>: <Start>\|<Length>@0+ (1,0) [0\|0] "" Vector__XXX`；Start = Byte×8 + bit 起始位 |
| 信号名 | 同 ini：C 列数据 sanitize 为合法 C 标识符，帧内去重 |
| `BA_` | `GenMsgSendType=Cyclic`、`GenMsgCycleTime=10`、`BusType=CAN1` |
| `VAL_` | 仅 1bit 信号附带 `0 "OFF" 1 "ON"` 值表 |

> 说明：ini 与 DBC 中的信号按"顺序起始位"编号（Byte×8 + bit），与 C 代码中的 `g_u8_tx_can_data` 字节布局一一对应；多字节信号（如 32bit 变量）Length = 32、跨 4 字节。

## 七、异常 & 边界处理

1. Sheet 名称存在非法 C 标识符字符：空格、`-`、`#`等，统一替换为下划线`_`；
2. A/B/C 三列格式错误（触发 3.4 / 3.5 / 3.6 任一规则：Byte 值非法、合并形态不符、Byte 序列不完整不连续、数据结束后又出现数据、B 列缺失或顺序错乱、C 合并跨组、多字节信号 Byte 不连续、信号名非法等）：均判定为格式错误，弹窗提示用户修正 Excel 后重新导入；
3. 同字节内信号 bit 区间发生重叠：后解析行覆盖前面数据，输出告警；
4. 信号位宽由 C 列合并格数直接确定，无需依赖 D 列类型，也不存在类型推断失败的场景。
