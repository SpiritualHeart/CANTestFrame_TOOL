1 软件概述

1.1 简介

CAN_TestFrame_TOOL 是一款运行于 Windows 平台的 CAN 测试帧代码生成工具。用户导入 I/O 枚举定义或 Excel 信号定义文件后，工具自动解析 CAN 信号在报文中的字节 / bit 布局，一键生成嵌入式 C 语言测试帧源代码，同时生成配套的上位机配置文件（.ini）与 CAN 数据库文件（.dbc），用于 CAN 总线台架测试、功能调试与信号监控。

1.2 功能模块

模块输入文件主要输出
IO枚举文本I/O 枚举定义 txt 文件（IOenum.txt）app_can_test_frame_01_input_output.c 及同名 .ini / .dbc
Debug表格信号定义 Excel 文件（.xlsx）全部测试帧函数的 .c 文件 + 每个工作表独立的 .ini / .dbc

1.3 输出产物

  • C 源文件（.c）：可直接编译的 CAN 测试帧 C 函数，未定义字节自动填充 0x00；
  • 上位机配置（.ini）：上位机报文 / 信号配置，Motorola 格式，Cycle=10，UTF-8 无 BOM 编码、Windows CRLF 换行；
  • DBC 数据库（.dbc）：兼容 Vector CANoe / CANalyzer 的 CAN 数据库，节点为 BCM，周期 10ms。
编码约定

生成的 ini / dbc 文件由工具按固定编码规则写出，请勿用其他编辑器另存，否则可能因换行符或 BOM 变化导致上位机无法识别。

2 运行环境与安装

  • 操作系统：Windows 10 / Windows 11（64 位）；
  • 无需安装任何依赖，双击 CAN_TestFrame_TOOL.exe 即可运行；
  • Debug表格 功能使用的 Excel 文件建议用 Microsoft Excel 或 WPS 表格编辑，并保存为 .xlsx 格式；
  • 查看 .dbc 文件需要 Vector CANoe / CANalyzer 或其他支持 DBC 的工具（如 CANdb++）。
提示

程序为单文件绿色软件，无需安装。若被杀毒软件误报，添加信任后重新运行即可。使用过程中可通过 帮助 → 使用教程查看本说明书（HTML 格式，自动在浏览器中打开）。

4 IO枚举文本 功能

4.1 功能说明

导入 I/O 枚举 txt 文件后，工具自动识别 NUM_OF_INPUTS / NUM_OF_OUTPUTS，将全部输入、输出信号按"每 8 个信号 1 字节、每 64 个信号 1 条 CAN 报文（8 字节）"的规则打包，生成测试帧 C 函数 app_can_test_frame_01_input_output()，并配套生成上位机 .ini 与 .dbc 文件。

4.2 输入文件格式要求

txt 文件中须包含两个 typedef enum 枚举块，且分别以 NUM_OF_INPUTS / NUM_OF_OUTPUTS 结尾：

typedef enum
{
    SI_J131_Clutch_H_IN,
    SI_J132_MLS_AUTO_IN,
    ...                      /* 依次列出全部输入枚举 */
    NUM_OF_INPUTS            /* 结束标记，必需 */
} INPUTS_ENUM;

typedef enum
{
    SO_HL_LOW_IN,
    ...                      /* 依次列出全部输出枚举 */
    NUM_OF_OUTPUTS           /* 结束标记，必需 */
} OUTPUTS_ENUM;

若未能识别到上述枚举块或结束标记，导入时会弹窗提示："未能识别 INPUTS_ENUM / OUTPUTS_ENUM 或 NUM_OF_INPUTS / NUM_OF_OUTPUTS 标记，请检查 txt 文件格式"。

4.3 操作步骤

1

导入

文件 → 导入 → IO枚举文本，选择 I/O 枚举 txt 文件（如 IOenum.txt）。

2

解析

导入成功后界面显示输入 / 输出枚举列表及生成的函数预览。

3

生成

点击界面右下角"生成"按钮。

4

填写 CAN ID

在弹出的 CAN ID 输入对话框中填写各报文的 16 进制 CAN ID（默认自 7E0 起连续顺延，可直接修改），点击"确定"。

5

保存

选择 .c 文件的保存位置，工具在同目录自动生成同名 .ini 与 .dbc 文件。

4.4 界面说明

  • 顶部文件名：显示已导入的文件名；
  • 信号统计：NUM_OF_INPUTS 与 NUM_OF_OUTPUTS 数量；
  • 枚举列表：左侧"输入枚举 / 输出枚举"两个页签，显示序号与枚举名称；
  • 函数预览：右侧实时显示生成的 C 函数代码（只读，等宽字体）；
  • "生成"按钮：点击后弹出 CAN ID 输入对话框并进入生成流程。

4.5 CAN ID 输入对话框

每 64 个信号占用 1 条 CAN 报文（8 字节 × 8 bit）。工具根据输入、输出信号数量计算所需报文数，并要求逐一填写 CAN ID。输入与输出报文使用不同的 CAN ID，互不共用。

提示

CAN ID 需以 16 进制填写（如 7E0，无需 0x 前缀）。留空点击"确定"会提示 "CAN ID 不能为空，请重新填写"。

4.6 输出文件

文件命名说明
C 源文件app_can_test_frame_01_input_output.c可编译的测试帧函数源码
上位机配置<同名>.ini报文 / 信号定义，Motorola 格式，Cycle=10
DBC 数据库<同名>.dbcCANoe / CANalyzer 可直接导入

4.7 生成规则要点

  • 输入信号自 byte 0 起，按 bit0 → bit7 顺序逐位打包；
  • 输出数据起始字节 = 输入所占 CAN 帧数 × 8，保证输入、输出数据分离在不同报文中；
  • 输入 / 输出末尾不足 8 bit 的字节按实际 bit 数赋值，其余位为 0；
  • 对齐到下一 CAN 帧边界的 padding 字节填充 0x00；
  • ini 中每条 $Message 的 Cycle 为 10，每个 1-bit 信号附带 #Value:0,OFF; / 1,ON; 值描述；
  • DBC 中 BO_ 使用十进制 CAN ID，消息发送节点为 BCM。

5 Debug表格 功能

5.1 功能说明

导入 Excel 信号定义文件后，工具跳过第 1 个工作表，从第 2 个 Sheet 起逐表解析 CAN 信号的字节 / bit 布局，为每个工作表生成一个 C 测试帧函数（命名 app_can_test_frame_<Sheet 名称>），并为每个工作表独立生成一份 .ini 与 .dbc 文件。

5.2 文件与工作表要求

  • 文件格式必须为 .xlsx；旧版 .xls 暂不支持，需先用 Excel 另存为 .xlsx 后再导入；
  • 文件需至少包含 2 个工作表（第 1 个被忽略）；
  • 每个工作表的参数表头行位于第 11 行（仅作参考，不参与代码生成），真实数据行从第 12 行起；
  • 工具在工作表前 20 行内查找表头行（A 列应为 Byte），找不到即判定格式错误。

5.3 列定义

Excel 列字段说明
A 列ByteCAN 帧内字节序号，取值 0~7；同一数值行属于同一字节分组
B 列Bitbit 编号；A 列为单格时必须为空
C 列Signal信号 / 变量名称；单元格纵向合并数量代表信号占用 bit 位数
D 列Type（可选）仅作人工备注，不参与解析与代码生成；信号位宽完全由 C 列合并格数决定
F 列IDCAN ID，支持 7E0、0x7E0、ID7E0 等写法

5.3.1 A 列（Byte 列）规范

A 列不为空时只允许以下两种形态，其他形态均视为格式错误：

A 列形态含义
单个单元格（无合并）该行数据占用完整 1 个字节（8bit）；此时 B 列必须为空
8 个单元格纵向合并该字节包含多位数据，合并范围内 8 行逐行定义 bit（B 列填 0~7）

补充约束：

  • 当前行 A 列为空表示数据结束，其后所有行的 A 列必须均为空；若其后仍出现 Byte 数据则报错；
  • Byte 数值必须以 0~7 一组一组完整出现：每组从 0 开始、连续递增、到 7 结束；一组未到 7 即停止（如止于 6）或跳号 / 重复均报错；
  • A 列为空的行，其 B / C 列不应再有数据（通常是漏填 Byte 列）；
  • A 列合并只允许纵向单列合并，不得横向跨列合并；表头行以上区域的装饰性合并不参与校验。

5.3.2 B 列（Bit 列）规范

场景规则
A 列为单个单元格B 列必须为空（该行占用完整 1 字节），非空即报错
A 列为 8 格合并组内 8 行 B 列必须依次填写 0、1、2、3、4、5、6、7：完整、不跳号、不重复
  • B 列不得使用合并单元格（数据区内）；
  • B 列值只能是 0~7 的整数。

5.3.3 C 列（Signal 列）规范

A 列形态C 列形态含义
单个单元格单格（无合并）整字节信号，生成代码时直接赋值
单个单元格为空该字节无数据（padding，填 0x00）
单个单元格纵向 n 格合并跨 n 字节的多字节信号（如 4 格合并 = 32bit 变量占 4 字节）；合并范围内 A 列 Byte 值必须连续递增
8 格合并单格1 bit 信号
8 格合并纵向 n 格合并n bit 信号（如 2 格合并 = 2bit），占用合并范围内 B 列对应的连续 bit
8 格合并为空该 bit 无数据（padding，填 0）

多字节信号标准表达示例（u32 变量 res_value 占 4 字节、u16 变量 res_value_ADDES 占 2 字节）：

BytebitSignal（C 列）
0res_value（C12:C15 合并）
1（合并范围）
2（合并范围）
3（合并范围）
4res_value_ADDES（C16:C17 合并）
5（合并范围）
6（无数据，padding）
7（无数据，padding）

补充约束：

  • C 列合并只允许纵向单列合并，不得横向跨列合并；
  • A 单格行上的 C 合并（多字节信号）允许且必须跨字节，合并行数即信号字节数；
  • 8 格合并组内的 C 合并（多 bit 信号）不得跨字节，只能在该字节组的 8 行范围内；
  • 信号名必须是合法的 C 表达式：以字母或下划线开头，可包含数组下标 [n]、成员访问 . 或 ->、函数调用 ()；不得包含中文；
  • 同一字节组内信号 bit 区间不得重叠（重叠时输出告警，后解析行覆盖前面数据）。

5.4 格式校验

导入 Excel 时工具自动校验 A / B / C 三列是否符合上述规则：

  • 错误——校验不通过：弹窗"文件格式错误"，逐条列出问题所在的工作表、行号与原因，需修正 Excel 后重新导入；
  • 告警——校验通过但个别行有问题：弹窗"格式告警"，列出被跳过的行（如 bit 区间重叠），其余行正常生成。

6 输出文件格式说明

6.1 C 源文件（.c）

  • 文件头部含说明注释：文件名、生成工具、NUM_OF_INPUTS / NUM_OF_OUTPUTS（IO枚举文本）；
  • 每个函数输出 8 字节 CAN 帧数据，帧字节顺序严格 Byte0 ~ Byte7；
  • Excel 中没有定义的字节默认填充 0x00；
  • 信号处理方式完全由位宽决定（与信号是函数还是变量无关）：
    • 位宽 = 8bit 且独占整字节：直接赋值；
    • 位宽 = 1bit：if (x > 0u) 条件置位 BITn；
    • 位宽 2~7bit：字节先清零，信号移位后按位或 |=；
    • 位宽 > 8bit：按大端序对每个涉及字节分别移位赋值。

6.2 ini 文件（上位机配置）

项目规则
文件编码UTF-8 无 BOM，Windows CRLF 换行
$MessageId（16 进制大写、无 0x）, 8, RX_<ID>, 10（长度 8、Cycle=10）
&FormatMotorola
@SignalStart, Length, Name, 0；Start = Byte×8 + bit 起始位，Length = 信号位宽
信号名取 Excel C 列数据，非法字符替换为 _，帧内重名自动加 _1 / _2 后缀
#Value仅 1bit 信号附带 0,OFF; / 1,ON; 值描述
帧间分隔每个 Message 块后空一行

ini 片段示例：

[$Message]
Id=7E0, 8, RX_7E0, 10
&Format=Motorola
@Signal=0, 1, SI_J131_Clutch_H_IN, 0 #Value:0,OFF; / 1,ON;
@Signal=1, 1, SI_J132_MLS_AUTO_IN, 0 #Value:0,OFF; / 1,ON;
...

6.3 DBC 文件

项目规则
节点BU_: BCM，所有消息发送方为 BCM，接收方 Vector__XXX
BO_BO_ <十进制ID> RX_<16进制ID>: 8 BCM（消息名统一 RX_ 前缀，如 RX_7E0）
SG_SG_ <信号名>: <Start>|<Length>@0+ (1,0) [0|0] "" Vector__XXX
BA_GenMsgSendType=Cyclic、GenMsgCycleTime=10、BusType=CAN1
VAL_仅 1bit 信号附带 0 "OFF" 1 "ON" 值表

DBC 片段示例：

BO_ 2016 RX_7E0: 8 BCM
 SG_ SI_J131_Clutch_H_IN : 0|1@0+ (1,0) [0|0] "" Vector__XXX
 SG_ SI_J132_MLS_AUTO_IN : 1|1@0+ (1,0) [0|0] "" Vector__XXX

BA_ "GenMsgCycleTime" BO_ 2016 10;
BA_ "GenMsgSendType" BO_ 2016 0;
VAL_ 2016 SI_J131_Clutch_H_IN 0 "OFF" 1 "ON" ;
起始位对应关系

ini 与 DBC 中的信号按"顺序起始位"编号（Byte×8 + bit），与 C 代码中 g_u8_tx_can_data 的字节布局一一对应；多字节信号 Length 为其总位宽（如 32bit 变量 Length=32）。

7 常见问题（FAQ）

Q1：导入 .xls 文件时提示"暂不支持旧版 .xls 格式"？

Debug表格 目前仅支持 .xlsx。请在 Excel / WPS 中打开该文件，另存为 .xlsx 后重新导入（文件 → 导入 → Debug表格）。

Q2：导入 Excel 后弹窗"文件格式错误"，提示多条规则问题？

Excel 不满足 5.3 节 A / B / C 三列格式规范。弹窗中每条提示均包含工作表名与具体行号，按提示逐条修正后重新导入即可。常见原因：Byte 序列未从 0 到 7 完整出现、数据结束后又出现 Byte、A 列合并不是 8 格、B 列缺失或顺序错乱、C 列合并跨组、多字节信号 Byte 不连续、信号名含中文等。

Q3：导入成功但弹窗"格式告警"，提示某些行已跳过？

文件整体合法，但个别行存在 bit 区间重叠等问题，这些行被跳过，其余行正常生成。请对照告警提示修正对应行后重新导入，以获得完整输出。

Q4：上位机无法识别生成的 ini 文件？

本工具生成的 ini 为 UTF-8 无 BOM、Windows CRLF 换行。若曾用其他编辑器修改并另存，可能引入 BOM 或 LF 换行导致识别失败，请使用本工具重新生成。

Q5：一个工作表里可以有多个 CAN ID 吗？

可以。同一 Sheet 内出现多个 ID 时按首次出现顺序分帧，每个 CAN ID 对应一个 8 字节测试帧，该 ID 行范围内的信号归入对应帧，分别体现在生成的 ini / dbc 中。

Q6：DBC 文件在 CANoe 中如何使用？

在 CANoe / CANalyzer 中通过 Database → Add 添加生成的 .dbc 文件即可。消息发送节点为 BCM，周期 10ms，信号起始位与 C 代码中的字节布局一致。

Q7：配置 → 清空 菜单的作用？

清空当前导入的全部数据并返回初始界面（"请先导入文件"），不删除已生成的文件。需要更换导入文件时可直接重新导入，无需先 Clear。

Q8：CAN ID 可以使用 0x 前缀或 ID 开头的写法吗？

可以。Excel F 列支持 7E0、0x7E0、ID7E0 等写法（大小写均可），工具统一提取为大写 16 进制。IO枚举文本 的 CAN ID 输入对话框中直接填写 16 进制数值（如 7E0）即可。

Q9：帮助 → 使用教程打开的是什么？

内嵌在程序中的 HTML 版使用说明书。程序自动将其释放到系统临时目录（%TEMP%\CAN_TestFrame_TOOL）后调用默认浏览器打开，左侧目录可点击跳转，方便在线查阅。

Q10：D 列（Type 类型说明）还需要填写吗？

不需要。工具的信号位宽完全由 C 列合并单元格数量决定，处理方式（直接赋值 / BITn 置位 / 移位或运算 / 拆多字节）全部按位宽自动选择，与信号是函数、BOOL 还是多字节变量无关。D 列仅作人工阅读备注，可保留旧内容、置空或整列删除，均不影响代码生成。
